# Product Principles

## 1. Simplicity Before Features

Never add a feature if improving an existing workflow solves the problem.

---

## 2. Reuse Before Creating

Before building a component:

- Search for an existing one.
- Extend it if possible.
- Only create a new component when necessary.

---

## 3. Progressive Disclosure

Show only the information needed for the current decision.

Additional details belong on a dedicated screen or dialog.

---

## 4. Performance is a Feature

Avoid unnecessary renders.

Use FlatList for long lists.

Optimise interactions for low-end Android devices.

---

## 5. Consistency Wins

Users should never wonder how a button, form, or list behaves.

Patterns should repeat throughout the application.

---

## 6. Accessibility by Default

Touch targets should be at least 48dp.

Support screen readers.

Maintain sufficient colour contrast.

Avoid relying solely on colour to communicate status.

---

## 7. Build for Growth

Every new feature should fit naturally into the existing architecture.

Avoid shortcuts that create technical debt.
